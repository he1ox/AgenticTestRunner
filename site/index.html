§ 01 · get started

Start with one flow.
Grow into a release gate.

qa-runner turns the coding agent you already use into a QA team that works your way. It plans the cases, tests them in a real browser and brings you the proof. You make every decision that matters, and each one is reused by the next run.

Perfect when

  • You test a web app by hand before each release and lose hours to clicks and screenshots.
  • You ship a feature or a fix and want proof it works before you hand it off.
  • You migrate a legacy system and need the new app to match the old one, case by case.
  • You want a regression gate in CI before anyone writes test code.

Your team already owns a Playwright suite as code? See how it compares.

  1. 01

    Install and set up you · once

    Run one command, then ask your agent to “set up qa-runner”. It checks Node, npx and ffmpeg, registers the browser and writes .qa/config.json with your app, accounts and variants.

    npx skills add he1ox/AgenticTestRunner
    Plugins for each agent ↓
  2. 02

    Say what to test you

    One flow, a feature or the whole app, in your own words or from a ticket, a spec or a pull request.

    “test the checkout flow with a coupon”
    “run the test cases for SHOP-42”
    “regression pass on the admin before the release”

  3. 03

    Approve the plan you

    The agent drafts the cases into .qa/plans/ and shows you the list. Nothing runs until you approve it, so a wrong assumption costs you a minute instead of a run.

  4. 04

    Agents test in a real browser agent

    For every expected result the Test Agent marks a screenshot, and it can record the tab. When it needs a value it doesn’t have, such as an approver account, it asks you in the viewer and waits.

    Watch an agent test ↓
  5. 05

    Review every verdict you

    Check the evidence in the viewer and pick Approve, Needs retest or Reject. Ask the agent what it saw. A retest reruns only the cases you rejected.

    See a review ↓
  6. 06

    Approve what it learns you

    Agents propose lessons about your app, and only the ones you approve are kept in .qa/memory/. Cases you approve become scripts that replay with no agent, at $0, and can gate your CI.

    See it compound ↓

Why your review matters

Agents do the clicking. You decide what counts. validate checks the evidence before you see a verdict, no verdict is final until you sign it off, and nothing is remembered until you approve it. Every decision lands in files in your repository that the agents read before the next run. The second run asks fewer questions than the first, and over time the agents test the way your team does.

§ 05 · replays, CI and export

$0

per replay. Every case you approve is saved as a script that replays later in its own headless browser, with no agent and no tokens. Same steps, same marked screenshots, same recording.

# gate the merge: exits 1 when a case fails

node qa-runs.mjs suite run smoke --ci --junit qa-junit.xml

# own the tests as code

node qa-runs.mjs export --tag smoke --out e2e/qa

npx playwright test --grep @smoke

When the UI changes on purpose, Repair with agent re-records only that case.

§ 08 · install

One command for any agent.

Or install the plugin for your agent, which also registers the browser. Pick one, not both, or every skill shows up twice.

npx skills add he1ox/AgenticTestRunner

Detects your agents and installs the four skills for each. Then ask your agent to “set up qa-runner” to register the browser once.

claude plugin marketplace add he1ox/AgenticTestRunner
claude plugin install qa-runner@AgenticTestRunner

Adds the 3-browser pool, dedicated Test Agents and model routing per tier. Restart Claude Code so the skills load.

codex plugin marketplace add he1ox/AgenticTestRunner

Then install qa-runner from /plugins.

copilot plugin install he1ox/AgenticTestRunner
gemini extensions install https://github.com/he1ox/AgenticTestRunner
